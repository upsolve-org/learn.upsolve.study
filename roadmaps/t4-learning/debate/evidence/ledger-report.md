# Debate: Create an approachable desktop and mobile tutoring webapp combining Jane Street's Socratic learning flow, per-skill progress, LearnHarness teaching UI, and Gizmo-style ease and enjoyment, self-hosted for about 100 users on one T4 GPU.

## Settled structure

- P1: Use a server-controlled tutoring sequence: material selection, diagnostic, editable skill map, one-question teaching turns, spaced review, and a mixed final assessment; the model supplies bounded explanations and questions while code decides the next state. Preserve the learner's ability to request a direct explanation, adjust difficulty, choose the next skill, or pause and resume.
- P2: Persist demonstrated skill levels 0-5 with cited attempt evidence, and show level/5 progress bars separately from session completion, recall due dates and engagement rewards. Require independent checks including later unaided recall for promotion, treat assisted answers as practice evidence, and show diagnostic levels as provisional until assessed.

- P3: Let school students upload their own selectable-text PDFs or paste notes, confirm an extracted outline and choose a chapter; asynchronously prepare source-linked skill cards, questions, answer rubrics and misconception hints, then serve short retrieval-grounded tutor turns. Start with text-dominant material and explicit unsupported-content handling for scans, handwritten work, diagrams, missing solutions and disputed claims; release additional formats only after extraction and grading checks.

- P12: Before implementation expands, cap assessment-feasibility work at one engineer-day plus a proposed 12 subject-review hours for one supported material family; require a named consenting qualified reviewer or verified answer-key/checker route, otherwise keep mastery unavailable for that content. Freeze a 200-case held-out grading and tutoring set, release only after the specified error gates pass, and invite 10-15 learners for a two-week pilot that measures delayed unaided performance without claiming efficacy from engagement. (12 proposed subject-review hours for initial feasibility gate, availability unconfirmed)
- P13: Make account ownership filters, source-only retrieval, validated durable state updates and cross-account attack tests mandatory before the invited school pilot; the model cannot authorize access or publish uploads. The operator must set target ages/jurisdictions, onboarding responsibility, retention and incident/dispute handling before inviting students, with unresolved requirements blocking that release rather than turning into an assumed future reviewer job.

## Rejected

- P8: An import-to-study-pack product with fixed quizzes and source excerpts could use the same progress UI and one small asynchronous model worker, making live tutoring optional after the quiz experience works. This reduces live GPU pressure and grading variability but delays the requested adaptive one-to-one tutor, so it is a fallback if the live quality or latency gates fail.. Why not: Does not deliver the requested adaptive tutor as the main product; retain only as a contingency requiring scope reconsideration.
